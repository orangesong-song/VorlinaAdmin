## 这是什么

**内容唯一真源 = Git 仓库。** 后台只编辑仓库里的 JSON，**绝不直接改写页面 HTML** ——
改了也会被下一次构建覆盖（静默丢内容）。发布走「预览 → 人工确认 → 构建」三步。

| | 谁负责 | 视觉特征 |
|---|---|---|
| **网站后台**（本仓库） | 内容编辑 · 发布 · GEO | 金色 + 墨黑 + 纸白，克制 |
| 外贸作战中心 | 询盘处理 · 客户 · 报价 · 跟单 | 业务操作向 |
| 官网 `vorlina-new/` | 面向买家的英文站 | 同一套视觉令牌 |

三者**共用同一个 Supabase 项目**，但**界面职责不重叠**：
后台的「询盘查看」是**只读**的，跟单请到作战中心。

## 视觉：和网站"是一套"是结构性的

**继承材质、压缩尺度** —— 不照搬网站的营销版式。

**继承**：色板 · 三套字体 · 发丝线（`1px #E2DCD2`，卡片与表格**不用阴影**） ·
金色 mono 编号标签（`11px / letter-spacing .16em / 全大写`）· 墨黑反色块 · **全程无圆角**

**压缩**：网站区块间距 `56–104px` → 后台 `24–32px`；最大标题 `74px` → `26px`；
衬线**只用于页面主标题与登录页**（数据密集处一律 Inter，更耐读）；
数字一律 mono（既是网站既有语言，也让列对齐好读）。

### 令牌同步（唯一真源 + 比对守卫）

```
../vorlina-new/preview/assets/css/main.css
        │  tools/sync-theme.py（只取 :root + @font-face）
        ▼
   theme/css/tokens.css        ← 后台唯一视觉真源
        │  python3 tools/sync-theme.py --check   ← 构建前跑
        ▼
   网站改了配色 → 后台不会自动跟随，但**会被报出来**
```

两个仓库不能共享 CSS 文件，所以 token 只能"复制一份"——**而复制就会脱节**。
守卫的作用不是让它自动同步，而是**不让它悄悄变成两个品牌**。

### 两条类名纪律（都踩过，会真咬人）

1. **侧栏是 `.rail`，不是 `.side`** —— 网站里 `.side` 表示「区块标题右侧的说明文字」。
   后台若把侧栏也叫 `.side`，内容区的 `<div class="side">` 会继承侧栏的
   `display:flex` + `height:calc(100vh - 40px)`，**把整页布局撑坏**。
2. **表格数字列是 `.n`，不是 `.num`** —— 网站里 `.num` 是「区块编号标签」
   （`display:block` + `margin-bottom:8px`），套到 `<td>` 上会把它变块级并撑坏行高。

> 通用教训：**复用网站的类名前，先 grep 它在网站 CSS 里的定义。**
> 后台与网站共享一套视觉语言，也就共享了命名冲突的风险。

## 权限模型（2026-09-19 拍板）

| 操作 | 谁能做 |
|---|---|
| 登录 / 编辑内容 / **发布** | 任何**有效成员** |
| **回滚**（线上整体退回） | **仅 boss** |
| 删除内容 / 管理成员 | boss |

⚠️⚠️ **不可省的前提：关闭自助注册。** 现有 RLS 里
`inquiries_staff_read ... to authenticated using (true)` 意味着
**任何登录账号都能读全部询盘**（公司、邮箱、电话）——
若后台开放注册，"注册 → 登录"就等于同时拿到**客户名单 + 网站发布权**。
⇒ 账号只能由管理员在 Supabase 添加。

**由"人人可发布"推出的两条硬约束**：
1. **五项发布闸门是硬门禁** —— 全绿才点亮「确认发布」（人工审核只剩"预览确认"这一道）
2. **发布留痕不可省** —— 谁 / 何时 / 变更清单 / 版本串
